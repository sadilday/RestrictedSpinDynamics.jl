Run Logging

RestrictedSpinDynamics is a quiet library: by default a calculation returns its NamedTuple and prints nothing. When you want an ORCA/Gaussian-style narrative of a run (what system was built, how big the basis and Liouvillian are, how the propagation progressed, and a final summary), opt into it through simulate.

Verbose simulate

using RestrictedSpinDynamics

ss = SpinSystem(; names = ["Ha", "Hb", "C"], isotopes = ["1H", "1H", "13C"],
                shifts = [10.0, -10.0, 0.0], couplings = [(1, 2, 5.0), (1, 3, 140.0)])

simulate(ss, 0.0:0.1:1.0; state = polarized(1:3, :z),
         observables = ["mz" => total_spin_op(3, :z)], verbose = :full)

renders

== RestrictedSpinDynamics run ==  v1.0.0
system: 3 spins (2x 1H, 1x 13C), 2 couplings
basis:  kmax=3  dim=64
L:      64x64  nnz=256  ~6.5 KB
setup:  basis 0.19s  L 0.08s
step 1/11  t=0.0  drift=0.0
...
summary: peak mz=1.5  drift=0.0  wall=0.42 s

verbose accepts:

  • false (default): silent, today's behaviour.
  • :summary: banner + system / basis / Liouvillian blocks + a final summary line. No per-step output.
  • :full (or true): everything in :summary plus per-section timings and a throttled per-step progress line, and it turns the trace-drift canary on so the reported drift is meaningful.

The return value is unchanged: logging is a pure side effect, so wrapping an existing call in verbose = ... never changes what you get back.

Two heavier diagnostics are opt-in because they cost extra:

  • dla = true adds the dynamical-Lie-algebra floor (dla_dimension); on a higher-spin system it reports the grade-floor and rank-ceiling via dla_report. This closure can be exponentially expensive; only enable it for small systems.
  • leakage = true adds a grade-leakage rate (leakage_rate), the flow out of the retained grade-kmax subspace that truncation neglects.

Choosing a Sink

io names where the log goes (default stdout). Pass a RunLog to tee the same output to a file and the console, which is what long, resumable runs want:

lg = RunLog(joinpath(outdir, "manifest.log"))    # file + stdout, flushed after every write
log_event(lg, "starting field sweep")            # timestamped ad-hoc line
simulate(ss, ts; state = ..., verbose = :full, io = lg)
close(lg)

The same lg serves both the structured run block (io = lg) and free-form timestamped events (log_event), so a script needs only one sink object.

Progress Hook for Custom Loops

If you call propagate directly (not through simulate), pass a progress callback to receive the same per-sample information the verbose run log uses:

propagate(basis, L, c0, ts; observables = obs,
          progress = p -> println("$(p.step)/$(p.nsteps)  drift=$(p.drift)"))

The callback is invoked at each sample point with (; step, nsteps, t, drift). It is wired on the Krylov CPU path (propagate, propagate_timedep); the dense, GPU, adaptive, sequence, and feedback routes do not emit progress.

API

RestrictedSpinDynamics.RunLog — Type
RunLog([path]; echo = true, append = true) <: IO

A logging sink that fans every write out to its destinations and flushes each, so progress survives a killed run. RunLog() writes to stdout; RunLog(path) writes to a file and (with echo = true) also to stdout, the dual sink long-running scripts want. Because it is an IO, print/println/show and io = RunLog(...) work directly; close shuts file sinks but never stdout.

Examples

lg = RunLog(joinpath(outdir, "manifest.log"))   # tees stdout + file
log_event(lg, "starting sweep")
simulate(ss, ts; state = ..., verbose = :full, io = lg)
close(lg)
source
RestrictedSpinDynamics.log_event — Function
log_event(io, msg) -> nothing

Write a timestamped, flushed line [yyyy-mm-dd HH:MM:SS] msg to io (a RunLog or any IO).

Examples

julia> log_event(stdout, "starting sweep")
[2026-09-26 14:03:11] starting sweep
