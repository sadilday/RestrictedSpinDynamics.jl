V1 Public API & Stability

What the stability tiers mean, and which exports are not yet stable. The stable tier is the numerics engine held to exact / cross-check tests: full-grade assembly reproduces exact diagonalization (spin-1/2, and the dense dᴺ Lindblad for higher spin), and every reduction (symmetry, coherence sectors, reachability) reproduces the full basis.

TierContract
Stablesemver: no rename or meaning change without a major-version bump
Stable, scope-limitedequally supported, but read the documented physical/scope caveat
Experimentalships and works, but the API may still change

Scope-limited stable symbols (the higher-spin spherical-tensor radix path (validated to machine precision against exact dᴺ references; read the per-site-dimension and quadrupolar caveats), the GPU backend, the batched ensemble, Weiss mean-field reduction, the secular coupling forms, region selection, the 1D-irrep symmetry path, the thermalized davies_jumps/bengs_levitt_jumps backends (whose Boltzmann fixed point is exact only to leading order in β), and each relaxation backend's validity window) are fully supported but carry a physical/usage caveat, documented at each symbol's docstring where it is read in context rather than duplicated here.

Naming Convention (v1)

KindConvention
TypesUpperCamelCase
Module-level constantsSCREAMING_SNAKE_CASE
Everything else exportedsnake_case

Well-known physics acronyms (BPP, CSA) stay all-caps inside type names, matching Julia stdlib (SVD, LU, QR); a mechanism's lowercase composer term and its UpperCamelCase model type deliberately pair (e.g. the csa builder and the CSARelaxation model).

A physical mechanism xxx uses a fixed suffix grammar ("second kind" is always spelled with words, never a digit):

Layers

One composer per specification surface (hamiltonian, dissipator, state, sequence, modulation); the verb layer (restricted_basis, build_liouvillian, propagate, expect) stays single-call. build_liouvillian is the only build_* (there is no build_hamiltonian).

propagate is the unified propagation verb: it dispatches on the type of the generator handed to it (a sparse L, a Hamiltonian PauliDict, a Modulation, a Vector{Segment}, an SLE (Ls, W) pair, a SymmetryBlocks, or an ExchangeNetwork), with keyword flags (method=:krylov|:dense, backend=:cpu|:gpu, adaptive) for execution variants. Every propagate_* name (propagate_dense, propagate_gpu, propagate_timedep, propagate_modulation, propagate_adaptive, propagate_sequence, propagate_sequence_adaptive, propagate_sle, propagate_blocks, propagate_ensemble) remains exported as a thin forwarder into the matching propagate method, so existing call sites are unchanged.

Return Values

Every propagate_* returns a NamedTuple that always leads with ts, traces; only genuinely scalar/vector results (steady_state, initial_rate) return bare values. Because propagate dispatches across generators, the fields beyond ts, traces depend on which one it was handed:

generator handed to propagatefields beyond ts, traces
sparse L (method=:krylov/:dense), PauliDict H (non-adaptive), Modulationdrift, trajectory
PauliDict H with adaptive=truedrift, dims, basis_history, dropped_mass
Vector{Segment} with adaptive=falseboundaries, drift, trajectory, final_state
Vector{Segment} with adaptive=trueboundaries, dims, basis_history, final_state
SLE (Ls, W)drift
SymmetryBlocksdrift (= NaN, not measured)
Ensembleper_block_traces, drift
ExchangeNetworkfinal (per-compartment; here traces is a per-compartment NamedTuple, not a Dict)
